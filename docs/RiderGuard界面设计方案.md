# RiderGuard · Fleet 管理界面方案

## 设计方向

以 Tesla Fleet 的车队运营思路为参考：先看车辆/骑手状态与位置，再处理异常，最后进入历史和分析。Tesla 官方 Fleet 页面强调实时位置、车辆状态与安全提醒；RiderGuard 将这些信息换成骑手、守护盒和风险事件。视觉上使用石墨黑导航、暖白工作区、紧凑的信息卡。品牌橙只用于当前操作、路线和风险关注点，不把整页做成霓虹大屏。

参考：[Tesla Fleet](https://www.tesla.com/en_qa/fleet)。

## 信息架构

| 一级入口 | 主要任务 | 优先展示 |
| --- | --- | --- |
| 总览 | 看车队整体状态和待办 | 在线设备、在途骑手、今日风险、待处理事件、位置分布 |
| 实时态势 | 快速查看车队实时状态 | 位置更新时间、速度、设备状态 |
| 地图与轨迹 | 在大地图中定位与复盘骑手 | 实时位置、轨迹回放、车速变化、设备列表 |
| 风险中心 | 完成事件闭环 | 事件等级、时间、位置、图片证据、AI 解释、处置状态 |
| 骑手管理 | 管理人与设备的关系 | 当前状态、绑定设备、最近行程、联系方式 |
| 设备管理 | 判断守护盒是否可靠 | 在线状态、电量、GPS、摄像头、最后心跳 |
| 轨迹回放 | 复盘行程和异常点 | 路线、速度曲线、时间轴、事件标记 |
| 数据分析 | 找到反复出现的风险 | 风险趋势、高风险路段、设备故障率 |
| 系统设置 | 管理账号和权限 | 若依已有的用户、角色、菜单等能力 |

## 首页优先级

1. 顶部四个真实指标，必须来自接口。数据不可用时显示“—”与原因，不能用演示数字伪装实时统计。
2. 中央地图占主要面积。位置点按正常、关注、高风险分层；点选骑手后显示设备健康度与最近事件。
3. 右侧风险队列按严重度和时间排序，直接进入核实与处置。
4. 下方保留骑手、设备、轨迹、风险四个工作入口；未开发模块明确标记待接入。

## 交互与状态

- 风险色只表达事件级别：正常绿、关注琥珀、高风险红。品牌橙用于操作和轨迹。
- 页面切换只做短淡入；局部请求使用局部加载。进入系统沿用骑手过场，页面首帧渲染后淡出。
- 地图和指标要同时显示“最后更新时间”。断线、位置过期与无设备上报是三种不同状态。
- 事件详情采用左侧证据与地图、右侧处置时间线，操作后保留上下文，不整页刷新。
- 窄屏将地图、风险队列纵向排列；重要告警始终靠前。

## 当前实现与后续接入

若依工作区已有总览、实时态势、地图与轨迹、风险处置、骑手与设备、规则与运维六个入口。指标和事件来自 Java 后端；独立地图工作区使用高德底图与 GPS 坐标转换，展示最新位置、近一小时轨迹、轨迹播放与车速曲线。风险处置可查看图片证据、事件详情和操作记录。设备运维显示上报与识别状态，趋势来自数据库事件统计。相关启动与角色设置见《RiderGuard_设备云端联调》。

待真实 STM32、摄像头和 4G 模块到位后，还需基于实拍图校准 YOLO 有效区域与阈值，并完成板级蜂鸣器、状态灯、断网补传和端到端验收。设备电量、摄像头硬件自检、固件版本和 AI 解释尚无上报数据来源，页面不会将其展示成已接入能力。


## 2026-09-26 工作区界面更新

- 主侧栏直接展示运营总览、地图与轨迹、风险处置、骑手与设备、规则与运维；后端已授权的系统管理及系统监控菜单放在“管理与维护”分组。演示、工作流、开发工具和框架推广入口不进入产品导航及菜单搜索；底层接口权限继续由后端控制。
- 默认关闭多页签和布局配置入口，取消业务页面重复导航。新的 `riderguard-layout-v2` 本地布局设置让旧版缓存不再覆盖本次布局；顶部保留搜索、全屏和账号操作。
- 统一 RiderGuard 注册文案、页脚、SVG 页签图标与异常提示；保留仓库原有开源许可证及技术依赖。
- 大地图支持收起详情面板、浏览器全屏、骑手搜索与位置跟随，手动拖动地图会停止跟随。最近照片使用设备接口的 `latest_image_id` 经已有鉴权照片接口读取；后台升级后才会返回该字段。详情卡展示规则限速，不表示设备已确认接收该规则。
- 风险事件采用紧凑横向列表，窄屏自动分为两列；每 15 秒刷新，页面不可见时暂停，保留已打开的详情。

验证：前端类型检查和生产构建、后端编译；独立样例页面验证导航、详情、搜索及面板操作。样例预览不替代真实设备和高德服务联调。


## 手机工作区适配

992px 及以下采用移动布局：底部固定总览、地图、事件、骑手、运维入口；侧边菜单仍由左上角展开，切换页面后自动收起。底部导航及页面留白包含手机安全区域，支持页面缩放。

地图页使用动态视口高度（dvh），隐藏重复标题工具栏；底部骑手面板默认收起，点击手柄或上下滑动可展开/收起，选择骑手后显示详情。面板内容独立滚动，保留地图操作区域。横屏低高度窗口进一步收紧顶部留白。移动端不依赖浏览器全屏 API。

事件详情在移动端从底部打开，提供明确关闭按钮、底部安全间距和可滚动内容。常用操作目标至少 44px，输入框使用 16px 字号，设备链路状态在窄屏改为分行呈现，不隐藏识别状态。

本轮验证范围：Vue 类型检查、生产构建及已有轨迹回归测试。浏览器预览因自动审批额度不足未执行，真机触控、软键盘及横竖屏视觉效果待复核。


### 手机交互补充

骑手面板展开后提供“骑手详情 / 切换骑手”两个入口，切换时滚动复位，长轨迹详情不再阻挡骑手列表。事件详情先显示加载反馈，失败可直接重试；关闭抽屉立即取消迟到响应的显示，保存操作返回后也不会重新打开用户已关闭的抽屉。此处取消的是前端显示更新，不中止已提交的后台处置操作。


### 风险事件独立工作区

桌面侧栏及手机底部导航统一显示“风险事件”，`/riderguard/events` 直接加载事件页面。总览保留数量和进入入口，移除完整风险列表并扩大地图区域。进入事件页面不再初始化总览的设备、规则和地图数据；已有事件详情链接及地图联动路径保持有效。
