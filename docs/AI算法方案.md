# AI算法方案

> **现行基线：[RiderGuard 当前实施方案](RiderGuard_当前实施方案.md)。** 以下内容分清首版与后续；已取消边缘端运行 YOLO 的旧设想。

## 1. AI系统目标

实现：

-   人员检测
-   道路识别
-   风险判断
-   异常分析

采用：STM32 采集与本地限速规则 + 云端 YOLO 人数检测；视觉大模型仅用于后续事件解释。

# 3. 人员密集检测

模型：

YOLO

首版只检测 `person`；`bicycle`、`vehicle` 分类属于后续独立任务。

流程：

    图片

    ↓

    人数统计

    ↓

    连续两张达到人数阈值进入密集状态；连续三张低于阈值退出

人数阈值由若依策略配置，YOLO 置信度由 AI 服务参数设置；模型失败不得当作 0 人。前方区域、误检和漏检须以真实车载照片校准。

------------------------------------------------------------------------

# 8. 云端大模型分析

大模型仅用于事件发生后的辅助解释，不参与设备端即时超速提醒或人群密集限速。

大模型不部署在盒端。

流程：

    异常事件

    ↓

    上传图片和数据

    ↓

    VLM分析

    ↓

    生成解释

输入：

    图片

    速度

    位置

    人员数量

输出：

``` json
{
"risk":"high",
"reason":"人员密集且速度过快",
"suggestion":"减速"
}
```

# 10. 部署方案

STM32：采集、缓存、上传、根据有效限速本地比较速度并驱动蜂鸣器/状态灯。

云端 Python 服务：运行 YOLO 行人检测，后续才扩展道路分割或 VLM；模型权重和训练数据不提交 Git。

若依：设备协议、限速配置、照片与轨迹、风险事件、处置审计和地图。当前本地启动默认 `mock`，真实 `yolo` 模式须部署权重并用实际 JPEG 验证。
