# 外卖安全维护系统——硬件配件采购与连接方案

> 版本：V1.0（原型机方案）  
> 目标：以 **STM32F407VET6** 为主控，完成骑手定位、测速、姿态检测、周期拍照、4G 上传及云端分析。  
> 设计原则：**终端只做采集与上传，AI/YOLO/大模型统一放到服务器端运行。**

## 3. 主控板

### STM32F407VET6

当前选定：

```text
STM32F407VET6 核心板
Type-C 接口
排针下焊
```

### 主要职责

- 读取 GNSS 经纬度与速度
- 读取 MPU6050 六轴数据
- 读取霍尔测速脉冲
- 控制 OV2640 周期拍照
- 控制 4G 模块联网与上传
- 实现设备状态管理
- 实现超速、倾倒、急刹等基础规则

### 不负责

- YOLO 推理
- 大模型
- 复杂道路视觉识别
- 1080P 实时视频编码

这些任务全部放到服务器端执行。

## 4. 摄像头方案

### 已选

**OV2640 200 万像素 JPEG 摄像头模块**

当前这款模块不是 SPI + FIFO 版本，计划采用：

```text
OV2640
   │
   ├── SCCB / I2C：配置寄存器
   │
   └── DVP 并行图像数据
           │
           ▼
      STM32F407 DCMI
           │
           ▼
           DMA
```

### 采集策略

不做实时视频。

```text
每 2~3 秒拍摄 1 张 JPEG
```

第一版建议从以下分辨率开始：

```text
640 × 480
或
800 × 600
```

如果服务器识别远处行人效果不够，再逐步提高分辨率。

### 云端流程

```text
OV2640
  ↓
JPEG
  ↓
STM32F407
  ↓
4G Cat.1
  ↓
服务器
  ↓
YOLO
  ├── 行人检测
  ├── 人数统计
  ├── 人群密度判断
  └── 道路场景识别
```

## 5. GNSS 定位方案

### 已选

```text
ATGM336H 系列模块
+ 已焊排针
+ 陶瓷有源天线
```

客服沟通中确认可选 F7N36 版本，**到货后建议再次检查模块丝印，确认具体是否为 ATGM336H-F7N36。**

### 连接方式

```text
GNSS                STM32F407

VCC   ───────────→  3.3V
GND   ───────────→  GND
TX    ───────────→  UART_RX
RX    ←───────────  UART_TX
PPS   ───────────→  GPIO（可选）
```

### 读取内容

STM32 解析 NMEA 数据，例如：

- 经纬度
- UTC 时间
- GNSS 速度
- 定位有效状态
- 卫星数量

### 注意

GNSS 天线尽量：

- 朝向天空
- 远离 4G 天线
- 不贴大块金属
- 不紧贴锂电池
- 不安装在封闭金属盒内部

## 6. 4G 通信方案

### 已选方向

使用 **Air780EP / M100M Cat.1 开发板**。

建议配置：

```text
AT 固件
+ 5~12V 供电版
+ 自弹 SIM 卡座
+ 不带定位版
+ 4G 天线
```

因为已经单独使用 ATGM336H 做 GNSS，所以 4G 板无需再购买带定位版本。

### 通信结构

```text
STM32F407
    │
    │ UART AT 指令
    ▼
4G Cat.1
    │
    ▼
互联网
    │
    ▼
服务器 API / TCP / HTTP
```

### 下单前 / 到货后必须确认

1. UART TX/RX 是否为 **3.3V TTL**。
2. 是否包含 4G 天线。
3. 供电输入是否确实为 **5~12V**。
4. 是否支持 STM32 通过 UART AT 指令控制。

### 为什么单独供电

4G 模块发射时瞬时电流变化较大，因此不要和主控共用一块小功率降压模块。

## 7. IMU 方案

### 已选

**GY-521 MPU6050 模块**

### 作用

- 急加速检测

- 倾倒检测
- 剧烈震动判断
- 碰撞事件辅助判断

### 接线

```text
MPU6050             STM32F407

VCC   ───────────→  3.3V
GND   ───────────→  GND
SCL   ───────────→  I2C_SCL

INT   ───────────→  GPIO（可选）
```

第一版使用 MPU6050 即可；最终 PCB 若需要提高性能，可再升级到 ICM-42688-P。

## 8. 霍尔测速方案

### 已选

**3144 霍尔传感器模块蓝板**

商品参数：

```text
工作电压：3.3~5V
数字输出：DO
模拟输出：AO（本项目不用）
检测到磁铁：输出低电平
未检测到磁铁：输出高电平
```

### 推荐接法

直接使用 3.3V 供电：

```text
霍尔模块             STM32F407

VCC   ───────────→   3.3V
GND   ───────────→   GND
DO    ───────────→   GPIO / Timer Input Capture
AO                  不接
```

### 工作原理

车轮安装一颗磁铁：

```text
车轮转一圈
   ↓
磁铁经过霍尔模块一次
   ↓
产生一次数字脉冲
   ↓
STM32测量两次脉冲间隔
   ↓
计算轮速
```

设车轮周长为 `L` 米，两次脉冲间隔为 `T` 秒：

```text
v(m/s) = L / T
v(km/h) = L / T × 3.6
```

后期可以同时使用：

```text
霍尔轮速 + GNSS速度
```

进行交叉验证。

## 9. 电池方案

### 原型机

选择：

```text
2S LiPo
7.4V 标称
1550mAh
```

能量约：

```text
7.4V × 1.55Ah ≈ 11.5Wh
```

适合原型机测试，不追求长续航。

### 电池接口

典型 2S LiPo 有两组接口：

```text
3针小接口
→ 平衡 / 检测接口
→ 连接 B3 平衡充电器

2针主电源接口
→ 充放电主线
→ 连接整机电源系统
```

---

## 10. B3 平衡充电器

### 已选

**B3 10W 2S/3S LiPo 平衡充电器**

本项目使用：

```text
2S / 7.4V
```

充电时连接电池的 **3 针平衡插头**。

### LiPo 使用注意事项

- 不要使用普通电源直接给 LiPo 充电。
- 使用 B3 等平衡充电器。
- 不要过度放电。
- 电池鼓包后停止使用。
- 充电时不要无人看管。
- 尽量在不易燃表面进行充电。

## 11. DC-DC 供电方案

### 已选

```text
3A 可调 DC-DC 降压模块 × 2
```

### 总体结构

```text
          2S 7.4V 1550mAh
                 │
              保险丝
                 │
              总开关
                 │
       ┌─────────┴─────────┐
       │                   │
       ▼                   ▼
 DC-DC #1              DC-DC #2
 调至 5.0V             调至 5.0V
       │                   │
       ▼                   ▼
 STM32F407             4G模块
     │
     ├── GNSS
     ├── MPU6050
     ├── 霍尔
     └── OV2640
```

### 非常重要

可调 DC-DC 到货后：

```text
1. 先只接电池
2. 不接 STM32
3. 不接 4G
4. 用万用表测量输出
5. 调整到约 5.00V
6. 断电
7. 再连接负载
```

建议输出范围：

```text
4.95V ~ 5.05V
```

不要在未测电压的情况下直接插 STM32。

## 12. 4G 电源滤波

建议在 4G 开发板电源入口附近增加：

```text
              +5V
               │
        ┌──────┴──────┐
        │             │
     470~1000µF      0.1µF
      电解电容         陶瓷电容
        │             │
        └──────┬──────┘
               │
              GND
```

用途：降低 4G 发射时的瞬时压降，减少模块掉线和 STM32 复位风险。

## 13. ST-LINK 下载与调试

### 已选

**ST-LINK V2 带线版**

连接：

```text
PC
 │ USB
 ▼
ST-LINK V2
 │
 │ SWD
 ▼
STM32F407
```

主要信号：

```text
ST-LINK            STM32F407

SWDIO  ──────────  SWDIO
SWCLK  ──────────  SWCLK
GND    ──────────  GND
NRST   ──────────  NRST（可选但建议）
```

### 注意

不要使用 ST-LINK 给整套外设供电。

STM32 和外围模块应由独立 5V / 3.3V 电源供电。

## 14. 接口分配建议

第一版推荐：

| 模块 | STM32 接口 |
|---|---|
| GNSS | UART |
| 4G Cat.1 | UART |
| MPU6050 | I²C |
| OV2640 | SCCB/I²C + DCMI + DMA |
| 霍尔测速 | GPIO 外部中断 / Timer Input Capture |
| ST-LINK | SWD |

后续在 CubeMX 中再根据 F407VET6 实际引脚进行最终分配，重点检查 **DCMI 与其他外设是否存在引脚复用冲突**。

## 15. 数据上传策略

### 实时小数据

```text
GNSS：1~10Hz
轮速：实时采样
IMU：50~100Hz采集
```

并不是所有原始数据都必须上传服务器。

STM32 可先做初步处理，例如：

```text
当前速度：28.6 km/h
GNSS：正常
急刹车：否
倾斜角：8°
设备状态：正常
```

然后按 1 秒左右周期上传状态包。

### 图片

```text
每 2~3 秒
   ↓
OV2640 拍照
   ↓
JPEG
   ↓
STM32
   ↓
4G
   ↓
服务器
```

服务器再进行视觉分析。

## 16. 推荐开发顺序

不要一次把所有模块全部接上。

### 阶段 1：STM32 裸板

```text
STM32F407
+ ST-LINK
```

完成：

- 烧录测试程序
- LED 闪烁
- UART 输出

### 阶段 2：IMU

```text
STM32 + MPU6050
```

完成：

- 加速度读取
- 陀螺仪读取
- 倾倒判断

### 阶段 3：霍尔测速

```text
STM32 + 霍尔模块
```

完成：

- 脉冲计数
- 轮速计算
- 超速判断

### 阶段 4：GNSS

```text
STM32 + ATGM336H
```

完成：

- NMEA 接收
- 经纬度解析
- GNSS 速度解析

### 阶段 5：4G

```text
STM32 + 4G Cat.1
```

完成：

- AT 指令
- SIM 卡联网
- TCP / HTTP 通信
- 状态数据上传

### 阶段 6：摄像头

```text
STM32 + OV2640
```

完成：

- SCCB 配置
- DCMI + DMA
- JPEG 采集
- 每 2~3 秒一张

### 阶段 7：图片上传

```text
OV2640 → STM32 → 4G → 服务器
```

### 阶段 8：电池供电

全部功能用实验室电源跑通后，再切换到：

```text
2S LiPo + 双路 DC-DC
```

## 18. 后续正式产品 PCB 可做的升级

原型跑通后，可以把多个开发板整合成一块 PCB：

```text
STM32F407
+ GNSS裸模块
+ ICM-42688-P
+ 4G裸模块
+ 电源管理
+ SIM卡座
+ 天线座
+ 摄像头接口
+ 霍尔接口
```

这样可以显著降低：

- 体积
- 接线数量
- 故障点
- 成本
- 功耗

并提高整机可靠性与外观完整度。

## 19. 当前项目核心结论

本项目第一版不需要 Jetson，也不需要树莓派。

当前方案为：

```text
STM32F407 负责采集 + 控制 + 上传
                  │
                  ▼
              4G 网络
                  │
                  ▼
         4 × RTX 3090 服务器
                  │
        ┌─────────┴─────────┐
        │                   │
       YOLO               大模型
        │                   │
        └─────────┬─────────┘
                  ▼
            后台管理系统
```

这套架构兼顾了：

- 成本
- 功耗
- 小型化
- 开发难度
- 云端 AI 能力
- 后续产品化空间

非常适合作为当前外卖安全维护系统的第一代硬件原型。
