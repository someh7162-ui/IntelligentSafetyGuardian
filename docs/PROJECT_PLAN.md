# 项目落地计划

## 第一阶段：框架落地与链路 MVP

- 引入 RuoYi-Vue-Plus 作为正式管理系统底座。
- 保留当前 FastAPI/Vue 最小代码用于原型验证，不再在其上重复实现通用后台能力。
- 在成熟框架中先完成设备、骑手、轨迹和风险事件业务模块。

- 设备端模拟器每秒生成定位、速度和设备状态。
- 后端接收 `POST /api/v1/location/upload`，保存轨迹。
- 前端首页展示设备数量、骑手数量、最近位置。
- MQTT 用于设备上行和实时事件，WebSocket 用于后台推送。

## 第二阶段：风险闭环

- 接入速度阈值、路线偏离、急刹、急转弯和倒地规则。
- 建立 `user`、`device`、`track`、`risk_event` 数据模型。
- 风险事件保存图片地址、位置、速度、等级和分析结论。
- 管理后台增加风险列表、详情和轨迹回放。

## 第三阶段：真实感知和 AI

- 接入 GNSS、MPU6050/BNO085、摄像头和 4G 模块。
- 边缘端运行轻量 YOLO，完成行人、车辆和障碍物检测。
- 增加道路语义分割与 GPS/视觉/IMU 风险融合。
- 高风险事件上传云端 VLM，返回原因和处置建议。

## 关键约定

- 所有时间使用 ISO 8601 UTC 字符串传输，服务端统一转换。
- `deviceId` 是设备端到云端的稳定主键，骑手绑定关系由后台维护。
- 端到端先保证“采集、上传、存储、展示、告警”闭环，再追求模型精度。
- 真实模型权重、采集数据、密钥和生产配置不提交到仓库。
